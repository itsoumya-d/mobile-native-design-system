# Planning Contract

Score opportunities by user impact, frequency or reach, native benefit, reuse,
implementation risk, and verification strength.

Every recommendation must include current-code evidence, user benefit,
selected capability IDs, target-framework implementation, likely files,
protected behavior, accessibility and motion consequences, risk, confidence,
verification commands, and acceptance criteria.

Each `mobile-native-screen-plan/1` must identify exactly one screen or coherent
flow, approved and protected files, current behavior, invariant signatures,
states, copy policy, motion, adaptive behavior, tests, human visual review, and
stop conditions.

Stop when route ownership, callbacks, data boundaries, dirty-file ownership, or
behavior verification is ambiguous. Do not solve uncertainty by expanding the
file scope.
